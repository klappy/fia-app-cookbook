# Generative Glass fit for FIA

This is a bounded static contract assessment, not an implementation order or a completed usability study. Generative Glass offers reusable presentation primitives; the inspected interfaces do not supply FIA’s guided playback, verified offline preparation or voice-driven configuration. Those behaviors need app-owned orchestration. The existing FIA kit illustrates possible composition, rather than establishing the product’s method or requirements.

The assessment reads Generative Glass at [`8d6b48d`](https://github.com/klappy/bt-design-system-generative-glass/tree/8d6b48dd93b6efa43305724a0cf320a85feabe5b), which remained upstream main when checked on September 15, 2026. It covers the root README and skill entry; ResourceCard, ResourceStack and SyncBadge types and implementations; LanguagePicker types; the FIA kit README, app and HTML entry; and only the necessary shared bootstrap/data structure. LanguagePicker implementation, the full component library, source-media accuracy and runtime behavior were not assessed.

The [requirements](../product/REQUIREMENTS.md) and [journeys](../product/JOURNEYS.md) remain proposals. The [released PoC status](../poc/NARRATION-MEDIA-STATUS.md) is separate implementation evidence: an app adaptation does not mean upstream has implemented a shared contract. No new components, assets, fonts, issues or application behavior were created by this study.

## What the FIA kit actually wires

The [kit README](https://github.com/klappy/bt-design-system-generative-glass/blob/8d6b48dd93b6efa43305724a0cf320a85feabe5b/ui_kits/fia/README.md) and app show version selection changing Scripture data, script, language and direction; key-term selection opening a sheet; search/filter state; theme changes; and a manually cycled sync indicator. These are observed source-level state transitions, not executed interaction tests (DF-08).

Listen, Record and Open in Aquifer lack action handlers in that app; its resource cards receive no `onOpen`. Those omissions are illustrative wiring gaps. They do not demonstrate working playback, recording, external opening or offline availability. The fixed 390×844 container and [390-width HTML viewport](https://github.com/klappy/bt-design-system-generative-glass/blob/8d6b48dd93b6efa43305724a0cf320a85feabe5b/ui_kits/fia/index.html) are sample dimensions, not responsive-device evidence. The entry loads external React/Babel scripts, a local bundle and shared bootstrap; the bootstrap can fall back to a component loader and fetch/transpile the app. No disconnected execution was tested, and a sync toggle supplies no download guarantee (DF-09).

The root README describes templates as entry points mounting the kits; the inspected shared bootstrap exposes that embedding mechanism. This assessment did not inspect the template files themselves or create a template. The fetched shared bootstrap includes embedded sample data, but only its field structure and boot code were assessed; no standalone resource body, font binary or media asset was retrieved or copied into the candidate. Repository examples and metadata do not establish permission for new redistribution.

## Shared core versus FIA ownership

The [core rule](https://github.com/klappy/bt-design-system-generative-glass/blob/8d6b48dd93b6efa43305724a0cf320a85feabe5b/readme.md#core-vs-app) is reuse by at least two of the three named apps; a block needed by only one remains in its app layer. That is a design-system rule, not evidence that a proposed media controller has a second consumer. This study did not validate one (DF-10).

Use existing presentation primitives where their contracts fit. Keep source/rights data, availability verification, guide ordering, discussion stops, media ownership and saved-position recovery in FIA’s layer. A future shared media proposal would need an actual second-consumer comparison and an app-independent contract before promotion. The present gap does not authorize either a separate FIA design system or an upstream implementation.

For proposed flow design, preserve three distinctions: opening a resource versus playing it; connectivity versus verified local usability; and discovering a language versus having its content or narration. Carry source identity through pause/inspect/return. These are derived design implications to test against J-01/J-02/J-04, not new ratified requirements. The [oral research overlay](../product/JOURNEYS.md#oral-audience-research-overlay) adds questions about participation and comprehension that a technically correct control does not answer.

## Existing upstream requests and remaining limits

On September 15, 2026, [issue 1](https://github.com/klappy/bt-design-system-generative-glass/issues/1) (connectivity/availability), [issue 2](https://github.com/klappy/bt-design-system-generative-glass/issues/2) (media-consumption contract) and [issue 3](https://github.com/klappy/bt-design-system-generative-glass/issues/3) (cookbook pointer) were open. Their bodies propose acceptance criteria; open does not mean accepted, scheduled or implemented. The pinned root and FIA READMEs still call the cookbook unreadable. Its published availability contradicts that statement; issue 3 is the existing correction route, with no duplicate request created here (DF-11).

This assessment does not certify accessibility, touch behavior, responsive layout, media quality, complete localization, rights clearance or field usability. LanguagePicker behavior beyond types, the full bundle, other components and actual second-consumer reuse remain unassessed. The released app’s own bounded receipts stay in its status record; neither they nor this static reading validate all proposed journeys. Any later fit decision should retain these limits and cite the specific contract and exercise that changed them.
