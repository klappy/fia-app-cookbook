# Harvest procedure

A harvest is a bounded review of source evidence that prepares proposed product knowledge. A completed retrieval does not by itself establish a correct interpretation or an approved decision.

1. **Bind the pass.** Name the authorized source subset, observed revisions, intended output and work limit in the private work record. Keep unread and unavailable scope visible. Check the current source index before consuming a derived manifest.
2. **Resolve evidence.** Use authorized original access. Reuse an unchanged verified receipt; reread only for a changed revision, a fidelity gap or a specific unanswered question. Preserve returned paging order and unresolved cursors. Do not bypass a rejected read.
3. **Prepare candidates privately.** Identify a requirement, constraint, policy, tension or decision candidate. Default to proposed, distinguish historical from current evidence, and retain a minimal source pointer. Attach evidence to an existing claim before creating another. Keep rich candidates transient unless an authorized project-owned private home exists.
4. **Check the exact projection.** Review the actual public wording independently for evidence, status and sensitive context. Publish no raw text or identifying source metadata. An authority-sensitive decision needs an observed authorized ruling; an unanswered question stays open.
5. **Record the result.** After the applicable review and publication gates, update the product knowledge, current state and harvest record consistently. Private coordination retains neutral provenance, revision and review receipts. Preserve prior status and supersession.

An unchanged pass should create no duplicate claims. A changed source should attach a witness or justify a new proposed claim. An interrupted retrieval should resume without missing or duplicating returned evidence. If those checks fail, return the change for repair rather than marking the pass complete.

At the work limit, return the observed result and remaining scope. A partial pass does not establish whole-history coverage and does not exclude an unread source class.

See [contribution rules](../AGENTS.md) and [source access](../SOURCES.md). No automatic harvest or monitoring is established by this procedure.
