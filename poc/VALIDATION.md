# Validation contract

The plan defines future acceptance; it supplies no passing result. Evidence must name exact app/source-manifest SHA, command exit code, browser/version, environment, observed date, screenshot/audio/readback path and reviewer. Avoid recording people or private source material. Simulated faults are valuable but remain labeled simulated. Production data tests use the selected pinned pack, not substitute fixtures.

Primary headed-browser target is Google Chrome 152.0.7977.83 on macOS 26.2 build 25C5048a, with 320/390px responsive checks. Record actual versions again at B3. Playwright Chromium automation is separately labeled and headless speech events cannot satisfy audible acceptance. Physical phones remain untested. At B3 start, probe actual speech/output observability with existing legitimate capabilities. No audio capture/perception tool is currently proven; system-output-only loopback may be used only if actually available, without microphone/ambient/private capture or bypass. If audibility remains unobservable, continue the implementation and return its usable artifact with the mandatory audible gate untested and overall partial.

## Required gates

1. **Source/pack gate (B1):** regenerate all 130 guide units from the pinned article and compare hashes; account for six sections, 39 pause coordinates and hidden S04 example region. Compare three versions × 13 verses against pinned sources. Resolve exactly 32 associated items with four explicit map aliases. Read metadata license and attribution for all selected sources. Fetch and inspect eight actual image files, type/dimensions/hash; verify actual image identity and legibility of the source-requested region labels before cue association; do not claim expert geographic correctness. Corrupt source, missing term, bad alias and mismatched digest must fail instead of fabricate content.
2. **Guided interaction gate (B2):** all six steps are reachable, source order preserved and source attribution accessible. Follow each of the 39 stops manually or with a state-machine acceptance test plus independent source readback. Show no next-unit advancement while discussing. Explicit examples reveal is required before S04-U017–U029 appear or speak. Open every resource type and return with the same guide unit/version. Keyboard, Escape, modal focus return, visible focus, reduced motion, 200% zoom and portrait layout (390×844 plus 320px width) are usable. No fixed clipped phone frame, inert controls or horizontal content loss.
3. **Real speech gate (B3):** on the named supported browser, use a real user gesture to start Scripture and guide narration. Record actual voice name/lang/localService, start/end/error events and visible state transitions. Separately observe audible output and source fidelity for short representative Scripture/guide segments. Test pause, continue, resource interruption, version/step change, stop and overlapping clicks. No old utterance may advance a new session. Include the longest source paragraph and inspect chunk continuity: no missing/repeated text, no completion before all chunks finish. A simulated adapter validates orchestration only. Voice unavailable/error behavior is an explicitly simulated negative case if actual denial cannot be induced. No speech-input test is required because microphone control is not selected.
4. **Real offline gate (B3):** save a full pack online with actual progress and verified final manifest. Stop the preview/network source or use genuine browser offline mode; close the app and reopen the known local URL from a fresh tab in the same profile. Verify shell, guide, all 39 verses, all 21 terms and eight images, not only cached API wrappers. Verify image `naturalWidth>0` and displayed content; check zero required-network dependence. Resume same unit/version. Select actual local voice and separately observe audible offline output. A simulated `navigator.onLine=false` does not satisfy this gate.
5. **Failure/recovery gate (B3):** interrupt/cancel download midway, fail one asset, supply wrong hash, inject quota failure, remove a required cache entry, delete the pack, reload and retry. Confirm no false Saved state, no loss of a valid previous pack during failed replacement, no automatic video download and no permanent dead end. Mark injected cases simulated. Storage estimates/eviction are uncertain; display actual known values and revalidate content.
6. **Independent fresh-seat gate (B4):** from a clean checkout, execute documented commands and open the actual preview without author coaching. Follow the scenario below against the exact candidate commit. Inspect source/provenance, repeat mandatory speech/offline evidence, inspect screenshots and all failed/unsupported states. Verify actual PR checks, attached review/Bugbot where required, no unresolved mandatory failure and merged commit readback. New commits after review require affected checks again.

## Fresh-seat scenario

Start without saved content. Choose Mark 1:1–13 and a source version. Read the synthetic-voice notice, begin Scripture, pause and replay. Start step one and verify it stops at each discussion question; use Continue deliberately. In step two, open the Jordan image/map at the source cue, inspect its attribution and close it; continue from the same unit. In step three verify scene/setting resources and storyboard stop. In step four conduct the two activity stops and confirm examples are hidden until requested. In step five inspect relevant terms, including both Lord senses and Desert/Wilderness; return without losing position. In step six complete oral turn-taking/practice using explicit controls, then Finish session. Nothing is recorded or assessed.

Save the selected pack and observe transferred progress, size and verified Saved. Reload offline and repeat representative navigation plus every saved resource readback. Speak saved Scripture and guide through an actual local voice; document audible output separately from API events. Verify online-only video links. Delete the pack, confirm the app no longer claims it is saved, then retry preparation. Inspect keyboard/zoom/narrow-width controls and a forced unavailable-voice state.

## Delivery evidence and verdict

App home: README.md with supported tested browser, exact commands, actual local URL, source/capability limitations and commit. `evidence/` contains sanitized machine results, source/asset manifest, screenshots and observed speech/offline record. Do not commit raw conversations, credentials, personal audio, fabricated screenshots or unreviewed private narratives. Public content attributions and generated synthetic test audio may be stored only if actually captured and appropriately labeled; an audio recording must not be invented from speech events.

Kitchen holds each dish's claim/fire/review/tests/readbacks and final meal verdict; cookbook holds source rationale, product findings and updated capabilities. Link actual homes rather than paste conflicting summaries. Required capabilities that fail mean partial completion. Technical success still leaves physical-phone coverage, audience validation, learning outcomes, corpus expansion, localization, original audio, spoken app-driving and production release untested or outside this PoC.
