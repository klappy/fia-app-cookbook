# Delivery learning from the bounded passage

Observed 2026-09-11; applies to this PoC, not a universal design claim.

The initial visual review accepted token use and functional behavior before comparing complete rendered views with the actual system. Subsequent review corrected this: inspect the complete stylesheet/component chain, compare relevant full views and explicitly justify adaptations. A selective primitive import does not establish design-system fidelity.

A fake media adapter missed a native fetch receiver failure. A fresh browser missed an existing saved shell that kept serving old code. The useful checks are therefore separate: source/unit fixtures, real browser media behavior and a real old-saved-to-current upgrade. Clearing storage would conceal the upgrade defect and discard progress.

A per-run generation cap did not govern future retries. Current preparation freezes approved inputs and counts uncertain attempts before requests; changed inputs or missing/corrupt previous output hold regeneration. The successful initial batch ledger remains labeled retrospective response recovery. No quota or provider-internal billing certainty is inferred.

Actual source/audio bytes, playback events and human-heard quality are three different evidence levels. The first two work here; the third remains unverified, keeping the result partial. Public findings preserve that boundary and keep private voice media and raw governing sources in their authorized homes.

Broader audience learning, field use and source history still need their own evidence. Completing one passage's technical validation does not complete those streams. See [capabilities](CAPABILITIES.md) and [validation](VALIDATION.md).
