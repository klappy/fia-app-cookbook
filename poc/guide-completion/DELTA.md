# Driver-seat delta — revised optional helper

This revision supersedes the initial plan's combined completion/navigation action and stricter Finish gate. The first challenge result is retained as historical CHALLENGE.json, not approval of this amendment.

Ran the canon driver's-seat prompt again over the narrowed plan, both language adapters, existing navigation/Finish contract and DS proposal. From the facilitator's seat, progress must be an optional memory aid while the session remains usable exactly as before. From the implementation seat, a separate ledger can project checks without taking control of workflow.

Changes made by this revision:
- Replaced Mark complete and continue with a small optional Mark complete/Undo control: marking never navigates or replaces Play/Next.
- Removed the proposed Finish migration and all-section gate: legacy Finish behavior and state remain unchanged.
- Clarified explicit marks versus visits as our design choice, not a user quotation or extra user-imposed requirement.
- Retained exact source ID/digest binding, separate language state, no historical backfill and derived step checkmarks.
- Added regression gates that empty, partial and full marks cannot alter Finish eligibility, position or playback.

Rejected: mandatory marking (turns helper into workflow gate); audio/visit-derived marks (insufficient evidence for facilitator acknowledgement); new Progress tab (no accepted need beyond inline surfaces); changing primary controls (unrequested navigation disruption).

System: optional mark/undo → bounded source-bound ledger → inline section/step checks. The existing playback, navigation and Finish flows remain independent and authoritative.
