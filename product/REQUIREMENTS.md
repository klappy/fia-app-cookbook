# Requirements in development

The [ten proposed framing claims](../claims/CLAIMS.tsv) remain unchanged. The entries below develop reviewed [historical support](../journals/support/SUPPORT-001.md); they are proposed product requirements, not approved decisions or implemented behavior. **Supported proposal** means the need or approach appears in reviewed evidence. **Acceptance hypothesis** means a new exercise inferred for validation. **Not filled** means no actual result or ruling exists.

Product constraints below express the scope being explored; they are not ratified governance. Persona assignments and journey ordering are hypotheses. Resolve exact historical witnesses through [Sources](../SOURCES.md#supporting-pass-001).

## R-01 — Pause and return to a shared resource

| Field | Working entry |
|---|---|
| Status | Supported proposal; not approved or implemented |
| Framing | FIA-002, FIA-003, FIA-004 |
| Support | [support 13](../journals/support/SUPPORT-001.md#sup-001-13), [support 17](../journals/support/SUPPORT-001.md#sup-001-17), [support 19](../journals/support/SUPPORT-001.md#sup-001-19), [support 24](../journals/support/SUPPORT-001.md#sup-001-24), [support 26](../journals/support/SUPPORT-001.md#sup-001-26), [support 28](../journals/support/SUPPORT-001.md#sup-001-28), [support 31](../journals/support/SUPPORT-001.md#sup-001-31) |
| Outcome / need | An oral learner or group should be able to follow related Scripture, questions and media without resource hunting interrupting engagement. |
| Proposed behavior | Present the relevant resource, make room to pause and discuss, and resume at the intended point. Guidance through dramatized questions should avoid supplying their answers. Prompt expression without requiring a recording. |
| Rationale / alternatives / dissent | Audible shared-device use was considered sufficient; synchronized multi-user state was not necessary for that historical scope. Individual use should remain possible. Automatic cues presume a known flow and must not erase the option to navigate deliberately. |
| Acceptance hypothesis | In a prototype, follow an identified resource, pause for discussion, inspect its referenced image and resume the intended content. Observe whether the group loses context and whether guidance reveals answers. This is a proposed exercise, not a tested success. |
| Dependencies / open questions | Resource relationships, cue alignment and the actual method sequence require verification. Who controls the device, what position must persist and how each medium resumes remain open. |
| Actual validation / authority ruling | Not filled |

| Outcome / need | A person should be able to prepare useful content for a phone without requiring the entire collection or exceeding available storage. |

| Field | Working entry |
|---|---|
| Status | Supported proposal; not approved or implemented |
| Framing | FIA-001, FIA-003 |

| Outcome / need | Oral learners should reach useful resources without learning a complicated app structure, while text remains available as an option. |
| Proposed behavior | Explore audio as the default with optional text, simple resource access and transitions that preserve spatial continuity. Allow preparation or individual engagement beyond possession of a team translation-tool device. |
| Rationale / alternatives / dissent | Oral-first is not oral-only. Swipes, gradual reveals and layered elements are alternatives to investigate, not proven cultural preferences. Independent access is a need, not an approved authentication design. |

| Dependencies / open questions | The remembered gesture research remains unverified. Audience assumptions, access requirements, language and accessibility needs require direct assessment. A distinct audience may warrant its own design investigation. |

## R-04 — Make resource cues reliable without closing the AI question

| Field | Working entry |
|---|---|
| Status | Supported proposal; not approved or implemented |
| Framing | FIA-004, FIA-007, FIA-009 |
| Support | [support 07](../journals/support/SUPPORT-001.md#sup-001-07), [support 24](../journals/support/SUPPORT-001.md#sup-001-24), [support 29](../journals/support/SUPPORT-001.md#sup-001-29), [support 30](../journals/support/SUPPORT-001.md#sup-001-30), [support 31](../journals/support/SUPPORT-001.md#sup-001-31), [support 32](../journals/support/SUPPORT-001.md#sup-001-32), [support 33](../journals/support/SUPPORT-001.md#sup-001-33) |
| Outcome / need | Referenced resources should appear when useful without requiring repeated manual searches. |
| Proposed behavior | Explore a repeatable tagged flow with audio alignment. Missing links might be prepared with AI before playback; a smaller model was another alternative if rules are insufficient. |
| Rationale / alternatives / dissent | Deterministic structure was argued to improve reliability and device reach. Dissent warned that making AI optional could indefinitely postpone the best experience for oral translators. Preserve both the desired benefit and this unresolved priority choice; do not present deterministic-first as unanimous. |
| Acceptance hypothesis | For a verified tagged sample, check every expected resource cue and deliberate navigation path. Separately investigate whether the same user benefit requires conversational assistance. Compare actual observations before selecting an approach. |
| Dependencies / open questions | Existing tags and timing completeness are unverified. No universal AI reliability claim, model benchmark or first-release decision follows from historical explanations. |
| Actual validation / authority ruling | Not filled |
